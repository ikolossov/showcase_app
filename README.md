# Showcase — минимальный кроссплатформенный нативный клиент + демостенд

Нативное приложение-витрина: показывает карточку товара с сервера, регистрируется
по QR и само себя обновляет.

```
showcase_app/
├── client/            Rust + egui/eframe (OpenGL) — нативный клиент
│   ├── src/main.rs      конфиг, запуск потоков
│   ├── src/store.rs     AppID, device_secret, токены (state.json)
│   ├── src/api.rs       HTTP-клиент (ureq, rustls)
│   ├── src/worker.rs    опрос товара → 401 → refresh → QR + поллинг /login
│   ├── src/updater.rs   проверка версии, загрузка, SHA-256, подмена, перезапуск
│   ├── src/ui.rs        экран товара и экран QR
│   ├── Dockerfile       кросс-сборка linux + windows (+ опционально UPX)
│   └── rust-toolchain.toml  одна версия Rust для Docker, Mac и CI
├── server/            Go (только stdlib) — сервер стенда + админка + тесты API
├── scripts/
│   └── build-macos.sh   сборка под macOS arm64 + x86_64 (на Mac / в CI)
├── .github/workflows/
│   └── build.yml        CI: тесты → linux+windows (Docker) + macos (раннер) → Release
├── releases/          каталог обновлений: положили файл → выпустили версию
├── dist/              результаты сборки
├── docker-compose.yml
└── Makefile
```

## Почему такой стек

| Критерий | Rust + egui (выбрано) | Go + Gio | Go + Fyne | Tauri / Electron |
|---|---|---|---|---|
| Размер бинарника | **5.6–7.1 МБ, с UPX ~2 МБ** | ~10–12 МБ | ~25–30 МБ | 3–10 МБ / 100+ МБ |
| Внешние зависимости | нет (GL/X11/Wayland через dlopen) | нет | нет | системный WebView |
| Кросс-сборка в контейнере | linux + windows из одного образа | windows — да, linux — cgo | везде cgo | сложно |
| «Нативность» | свой GPU-рендер, одно окно | то же | то же | веб-страница в окне |

Сервер стенда написан на Go: это вспомогательная часть, к его размеру требований нет
(образ из `scratch` весит 13.9 МБ).

## Быстрый старт

Нужен только Docker. Все сборки (сервер и клиент) идут в контейнерах.

```bash
make server-up
```

```bash
make client VERSION=1.0.0
```

```bash
make run VERSION=1.0.0
```

- Админка стенда: <http://localhost:8780/admin>
- `make client` кладёт в `dist/` бинарники `showcase-1.0.0-linux-x86_64` и
  `showcase-1.0.0-windows-x86_64.exe`.
- Адрес сервера зашивается в клиент при сборке и попадает в QR. По умолчанию это
  IP машины в локальной сети, чтобы QR открывался с телефона. Переопределить:
  `make client SERVER=http://10.0.0.5:8780` или переменной `SHOWCASE_SERVER` при запуске.
- `make run` копирует бинарник в `demo/showcase` и запускает его с короткими интервалами
  для стенда: товар раз в 15 с, обновления раз в 10 с. Данные стенда (AppID, токены)
  лежат в `demo/data`, `make clean` их удаляет.

### Полноэкранный режим

Приложение стартует во весь экран, интерфейс масштабируется под разрешение экрана (от 1× до 4×).
После самообновления новый процесс снова открывается во весь экран.

- **F11** — переключить полноэкранный режим, **Esc** — выйти из него;
- `SHOWCASE_WINDOWED=1` — запуск в обычном окне (для разработки).

Полноэкранный режим выставляет оконный менеджер (KDE, GNOME, Windows, macOS). В «голом»
X-сервере без WM (например, Xvfb) окно останется обычного размера. Для киоска на Linux
используйте любой WM или Wayland-киоск (`cage`).

Windows: скопируйте `dist/showcase-1.0.0-windows-x86_64.exe` на ПК в одной сети со
стендом и запустите. Консоль не нужна, адрес сервера уже зашит.

## Сценарий демонстрации

1. **Первый запуск.** Клиент генерирует AppID (UUID v4) и секрет устройства и
   сохраняет их в `state.json`. Запрос товара без токена получает **401**, клиент
   показывает **QR** со ссылкой `http://<сервер>/register?app_id=<AppID>` и начинает
   раз в 2 с поллить `POST /api/v1/login`.
2. **Регистрация.** Сканируете QR телефоном → страница «Регистрация устройства» →
   «Привязать устройство». То же самое можно сделать кнопкой «Привязать» в админке.
3. **Получение токенов.** Ближайший `/login` возвращает пару access/refresh. Клиент
   сохраняет её и сразу показывает товар. Цена на сервере «гуляет» раз в 20 с,
   кнопка «Обновить сейчас» запрашивает товар вне очереди.
4. **Refresh.** На стенде access-токен живёт 2 минуты (`ACCESS_TTL`). Когда он
   истекает, клиент получает 401, тихо обменивает refresh-токен на новую пару и
   продолжает работу без QR.
5. **Обновление бинарника:**
   ```bash
   make release VERSION=1.1.0
   ```
   Команда собирает новую версию и кладёт её в `releases/`. В течение 10 с клиент
   скачивает файл, сверяет SHA-256, подменяет себя и перезапускается. В заголовке
   окна появляется `Showcase 1.1.0`, QR не показывается: авторизация сохранилась.
   В админке появится событие «клиент перезапустился на новой версии 1.0.0 → 1.1.0».
6. **Отзыв доступа.** «Отозвать» в админке → следующий запрос товара даёт 401,
   refresh тоже отклоняется → клиент снова показывает QR.

В продакшене интервалы по умолчанию 10 минут: `SHOWCASE_PRODUCT_INTERVAL=600`,
`SHOWCASE_UPDATE_INTERVAL=600`.

## Сборка под все платформы

| Платформа | Где собирается | Команда | Результат в `dist/` |
|---|---|---|---|
| Linux x86_64 | Docker | `make client VERSION=1.2.3` | `showcase-1.2.3-linux-x86_64` |
| Windows x86_64 | Docker (mingw) | та же команда | `showcase-1.2.3-windows-x86_64.exe` |
| macOS arm64 + x86_64 | Mac (Xcode CLT + rustup) | `make client-macos VERSION=1.2.3` | `showcase-1.2.3-macos-aarch64`, `…-macos-x86_64`, `…-macos-universal` |
| все сразу | GitHub Actions | `git tag v1.2.3 && git push --tags` | GitHub Release + `SHA256SUMS` |

Почему macOS не в Docker: для линковки нужен macOS SDK из Xcode, а лицензия Xcode
разрешает использовать его только на технике Apple. Поэтому:

- **локально** на любом Mac:
  ```bash
  xcode-select --install
  ```
  ```bash
  curl https://sh.rustup.rs -sSf | sh
  ```
  ```bash
  make client-macos VERSION=1.2.3 SERVER=http://10.0.0.5:8780
  ```
  Скрипт `scripts/build-macos.sh` собирает обе архитектуры (минимум macOS 11), подписывает
  бинарники и делает универсальный файл через `lipo`.
- **в CI** — job `macos` в `.github/workflows/build.yml` на раннере `macos-14`.

Подпись под macOS:

- По умолчанию **ad-hoc** (`codesign -s -`). Этого достаточно, чтобы бинарник запускался.
  Самообновление качает файл своим HTTP-клиентом, без атрибута карантина, поэтому
  Gatekeeper его не блокирует.
- Для раздачи пользователям нужны `MACOS_SIGN_IDENTITY="Developer ID Application: …"` и
  `NOTARY_PROFILE` (профиль `xcrun notarytool store-credentials`): скрипт подпишет файлы
  с hardened runtime и отправит их на нотаризацию.
- В CI это секреты `MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, `MACOS_SIGN_IDENTITY`,
  `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD`. Описание — в шапке `build.yml`.
- Если файл скачан браузером, macOS повесит на него карантин. Снять:
  ```bash
  xattr -d com.apple.quarantine showcase-1.2.3-macos-aarch64
  ```

Имена файлов совпадают с тем, что клиент спрашивает у сервера обновлений
(`os` = `linux` | `windows` | `macos`, `arch` = `x86_64` | `aarch64`). Чтобы выпустить
версию, достаточно положить все файлы релиза в `releases/`. `make release` на Mac
дополнительно соберёт и macOS-версии.

Версии зафиксированы для воспроизводимости:

- Rust `1.99.0` (`client/rust-toolchain.toml` и образ `rust:1.99.0-slim-bookworm`);
- Go `1.27.1` (`golang:1.27.1-alpine`);
- UPX `5.2.1` (с проверкой SHA-256);
- зависимости — `Cargo.lock`.

## Тесты

```bash
make test
```

- **Сервер (Go):** полный сценарий устройства через `httptest`:
  - 401 → `/login` 202 → 403 при чужом секрете → привязка → токены → товар;
  - одноразовый refresh и инвалидация старого access;
  - отзыв доступа;
  - истечение TTL access-токена;
  - выбор свежего релиза под платформу (1.10 > 1.9);
  - сравнение версий.
- **Клиент (Rust):** юнит-тест форматирования цены.
- В CI тесты гоняются перед сборкой. `cargo check` для `aarch64/x86_64-apple-darwin`
  проходит и в Linux-контейнере, линковки там нет.

## Размер бинарников (x86_64, release: LTO, `opt-level=z`, `panic=abort`, strip)

| Вариант сборки | Linux | Windows |
|---|---|---|
| полный: HTTPS + X11 + Wayland (по умолчанию) | 7.11 МБ | 5.57 МБ |
| полный + UPX (`make client UPX=1`) | **2.22 МБ** | **1.84 МБ** |
| без TLS (`--no-default-features --features x11,wayland`) | 6.18 МБ | 4.72 МБ |
| только X11, без TLS | 5.74 МБ | 4.72 МБ |

- Windows-exe зависит только от системных DLL (user32, opengl32, ws2_32…).
- Linux-бинарник линкуется только с libc/libm/libgcc_s (glibc ≥ 2.36). X11,
  Wayland и OpenGL подгружаются через `dlopen` во время работы.
- Из шрифтов egui встроен только Ubuntu Light (с кириллицей) вместо полного набора
  с emoji. Это экономит ~1 МБ.
- UPX сжимает примерно в 3 раза, но добавляет ~100 мс на распаковку при старте, а
  на Windows иногда даёт ложные срабатывания антивирусов. Поэтому по умолчанию он
  выключен.

## API сервера

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/api/v1/product` (`Authorization: Bearer`) | 200 товар / 401 |
| `POST` | `/api/v1/login` `{app_id, device_secret}` | 202 pending / 200 `{access_token, refresh_token, expires_in}` / 403 |
| `POST` | `/api/v1/token/refresh` `{refresh_token}` | 200 новая пара (refresh одноразовый) / 401 |
| `GET` | `/api/v1/update?os=&arch=&version=` | 200 `{version, url, sha256, size}` / 204 |
| `GET` | `/download/<файл>` | бинарник |
| `GET/POST` | `/register?app_id=` | страница привязки (открывается по QR) |
| `GET` | `/admin` | админка стенда |

Клиент шлёт заголовки `X-App-ID`, `X-App-Version`, `X-App-Platform`, поэтому в
админке видно версию и платформу каждого устройства.

## Как устроено самообновление

1. `GET /api/v1/update` → есть версия новее текущей.
2. Потоковая загрузка во временный файл рядом с бинарником (тот же раздел диска)
   с подсчётом SHA-256 на лету. При несовпадении хеша обновление отменяется.
3. Подмена бинарника через `self_replace`: на Unix это атомарный `rename`, на
   Windows работающий `.exe` переименовывается и удаляется после выхода.
4. Перезапуск с теми же аргументами: на Unix `exec()` (PID сохраняется), на
   Windows запуск нового процесса и выход из старого.
5. AppID и токены лежат не рядом с бинарником, а в каталоге настроек пользователя,
   поэтому новая версия стартует уже авторизованной. Пути:
   - Linux: `~/.config/showcase/state.json`;
   - Windows: `%APPDATA%\showcase\state.json`;
   - macOS: `~/Library/Application Support/showcase/state.json`;
   - переопределение: `SHOWCASE_DATA_DIR`.

## Безопасность

- AppID публичен (он в QR), поэтому `/login` требует ещё и `device_secret`. Его
  знает только само устройство, сервер привязывает его при первом обращении. Зная
  только AppID из QR, чужие токены не получить.
- `state.json` пишется атомарно (tmp + rename), на Unix с правами `0600`.

## Проверено на стенде

- **На рабочем столе этой машины** (KDE Plasma, Wayland, 3840×2160):
  - приложение открылось во весь экран, интерфейс отмасштабирован;
  - QR → привязка → товар;
  - `make release VERSION=1.1.0` → загрузка, подмена и перезапуск с тем же PID снова во
    весь экран, без повторной авторизации;
  - отзыв доступа → QR.
- `make test` проходит, `cargo clippy` без замечаний, `cargo check` под оба macOS-таргета
  без ошибок; `actionlint` и `shellcheck` чистые.
- Linux-клиент (обычный и UPX) в Xvfb-контейнере:
  - первый запуск → 401 → QR (декодирован, ссылка верная) → привязка → токены → товар;
  - автообновление 1.0.0 → 1.1.0 с перезапуском без потери авторизации;
  - отзыв → QR;
  - переживает перезапуск сервера: устройство снова появляется в списке ожидающих.
- Windows-exe собирается и линкуется только с системными DLL, но на реальной Windows
  в рамках стенда **не запускался** (wine в окружении нет).

## Ограничения и что сделать для продакшена

- **macOS** собирается скриптом/CI, но в рамках стенда на реальном Mac **не запускался**
  (проверена только компиляция). Раздаётся голый бинарник. Если понадобится `.app`-бандл,
  учтите: подмена бинарника внутри подписанного бандла ломает его подпись, поэтому
  обновлять придётся бандл целиком.
- **Подпись релизов.** Сейчас целостность проверяется SHA-256 из того же сервера.
  Для продакшена нужна подпись ed25519 с публичным ключом, зашитым в клиент. Плюс
  обязательный HTTPS: rustls уже включён фичей `tls`.
- **Откат.** Стоит хранить `.old`-копию и откатываться, если новая версия не
  смогла достучаться до сервера за N секунд после старта.
- **Сервер стенда.** Состояние в памяти, админка без авторизации — это только демо.
